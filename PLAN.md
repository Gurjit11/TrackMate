## 1. What we are building

**TrackMate** is a small agent that investigates a delivery problem. Input: a tracking ID (may be missing) and a user question. Output: one decision, a reply grounded in tracking data and cited policy clauses, and, when needed, a drafted message that waits for human approval.

**Decisions (the only three allowed):** `update`, `ask_info`, `escalate`.

**Fixed technical choices (do not change):**

| Item | Choice |
|---|---|
| Language | Python 3.11 or newer |
| API | FastAPI + Uvicorn |
| LLM wrapper, embeddings, retriever | LangChain with `langchain-google-genai` (Gemini) |
| Vector store | Chroma, local, persisted in `.chroma/` (use `langchain-chroma`) |
| Schemas | Pydantic v2 |
| Orchestration | Custom loop in `app/agent.py` (NOT LangGraph, NOT an agent framework) |
| Shipment data | Local JSON file, simulated |
| Message sending | Dry run: writes to `outbox.jsonl` only |
| Weather (M5 only) | Open-Meteo, free, no API key |
| Tests | Plain Python scripts, no pytest required |

**Environment variables** (`.env`, loaded with `python-dotenv`):

```
GOOGLE_API_KEY=            # Gemini API key (verify the exact variable name against the langchain-google-genai docs)
GEMINI_MODEL=              # chat model name; chosen in M0 from the list script
```

## 3. Shared definitions (used by every milestone)

### 3.1 Simulated "today"
Every shipment record has `as_of_date`. All shipments use `2026-11-02`. The agent must treat that as today. Never use the real system date for shipment logic.

### 3.2 Derived fields (computed in CODE in `data_access.py`, never by the LLM)
Given a shipment record, compute:

| Field | Definition |
|---|---|
| `days_past_estimate` | If `status` is `delivered`: 0. Otherwise `max(0, as_of_date - estimated_delivery)` in whole days. |
| `days_since_last_scan` | `as_of_date` minus the date of the latest event's timestamp, in whole days. |
| `days_since_delivered` | If `status` is `delivered`: `as_of_date - delivered_date`. Otherwise `null`. |
| `customs_hold_days` | If `exception` is `customs_hold`: `as_of_date - customs_hold_started`. Otherwise `null`. |

All dates are `YYYY-MM-DD` strings; compute with `datetime.date`.

### 3.3 Decision rules (the agent must follow these, in this order)

1. If there is no tracking ID, or the tracking ID is not found → `ask_info`.
2. If the shipment's `exception` is one of `address_incomplete`, `recipient_unavailable`, `customs_documents_required` → `ask_info`.
3. If ANY of the following is true → `escalate`:
   - `exception` is `damaged`
   - `days_since_last_scan >= 7` (and status is not `delivered`)
   - `status` is `delivered` AND the user says they did not receive it AND `days_since_delivered >= 2`
   - `exception` is `customs_hold` AND `customs_hold_days > 5`
   - `days_past_estimate > 3`
   - the user explicitly asks for a refund AND `days_past_estimate > 10`
4. Otherwise → `update`.

Weather NEVER changes the decision. It is only extra context in the reply (M5).

### 3.4 Message drafting rules
- `escalate` → draft an **email** to the courier support desk containing: tracking ID, last known event (date, location, description), the problem, and the policy clause(s) relied on.
- `ask_info` → draft a **whatsapp** message to the user listing exactly what information is needed.
- `update` → no draft (`draft_message` is `null`).
- Drafts are never sent automatically. Status starts as `pending_approval`.

## M2: Agent loop with guardrails (CLI only)

**Goal:** the core agent, runnable from the command line, with all guardrails enforced in code.

**Steps**
1. `app/schemas.py` per **Appendix D** (copy field names and types exactly).
2. `app/prompts.py`: put the system prompt from **Appendix C** in a constant `SYSTEM_PROMPT`. Do not paraphrase it.
3. `app/llm.py`:
   - `get_llm()` returns the Gemini chat model configured with `GEMINI_MODEL`, temperature `0`.
   - `call_structured(messages, schema)`: calls the model with structured output for the given Pydantic schema; retries up to 3 times with exponential backoff (1s, 2s, 4s) on rate limit (429) or server (5xx) errors; raises after the third failure.
4. `app/tools.py`:
   - `get_shipment(tracking_id: str) -> dict`. Normalize the ID. If found return `{"found": true, "shipment": <record>, "derived": <derived fields>}`. If not found return `{"found": false, "tracking_id": <normalized id>}`.
   - `search_policies(query: str) -> dict` returning `{"results": [ {doc, clause_id, title, text}, ... ]}` from `rag.search`.
   - (No weather tool yet.)
5. `app/agent.py`, function `run_agent(tracking_id: str | None, question: str) -> AgentResult`:
   - Build messages: system message = `SYSTEM_PROMPT`; first human message = JSON of `{"tracking_id": ..., "question": ...}`.
   - Loop up to `MAX_AGENT_STEPS` (6) iterations. Each iteration:
     1. Call `call_structured(messages, AgentStep)`.
     2. If `action == "call_tool"`: execute the named tool with the step's arguments, record the result, append the step (as an assistant message containing the step JSON) and a human message `TOOL RESULT (<tool>): <json>` to the messages, continue.
     3. If `action == "final"`: run guardrails (below). If a guardrail rejects it, append a human message `GUARDRAIL: <reason>. Fix this and return a corrected final answer.` and continue (this retry is allowed ONCE per run). Otherwise accept and stop.
   - Keep a set `retrieved_clauses` of `(doc, clause_id)` pairs returned by every `search_policies` call in this run.
   - **Guardrails (all enforced in Python, not just in the prompt):**
     - **G1, shipment lookup required:** if a tracking ID was provided and `get_shipment` was never called before `final`, reject (reason: "You must call get_shipment before answering").
     - **G2, not found forces ask_info:** if any `get_shipment` result had `found: false`, or no tracking ID was provided, then set `decision = "ask_info"` in code regardless of what the model said, set `missing_info` to `["a valid tracking ID"]` if it is empty, and add flag `forced_ask_info`.
     - **G3, citation validity:** every `(doc, clause_id)` in `final.citations` must be in `retrieved_clauses`. If not, reject (reason: list the invalid citations). If it is still invalid after the one allowed retry, set `decision = "escalate"`, replace `reply_to_user` with exactly `I could not verify this against policy, so I am escalating it for human review.`, set `citations = []`, and add flag `invalid_citation_escalated`.
     - **G4, step limit:** if the loop ends without an accepted final, produce a result with `decision = "escalate"`, the same fixed reply as above, and flag `step_limit_reached`.
     - **G5, draft rule:** if `decision == "update"`, force `draft_message = None`. If `decision` is `escalate` or `ask_info` and `draft_message` is `None`, reject once (reason: "Draft a message per the drafting rules"); if still missing after the retry, leave it `None` and add flag `draft_missing`.
   - After finishing, save a trace via `trace.py` (M2 can save the trace as a JSON file; M3 reads it back) and return `AgentResult` including `run_id`.
6. `app/trace.py`: `new_run_id() -> str` (uuid4 hex), `save_trace(trace: dict)` writes `traces/{run_id}.json`, `load_trace(run_id) -> dict | None`. Trace format per **Appendix D**.
7. `scripts/cli.py`: `python scripts/cli.py --tracking-id TM1006 --question "Why is this so late?"` prints the decision, reply, citations, missing info, draft, guardrail flags, and the run_id. `--tracking-id` is optional.

| `--tracking-id TM1006 --question "Why is this so late?"` | `escalate`, cites `courier_delivery_policy:1.3`, email draft |
